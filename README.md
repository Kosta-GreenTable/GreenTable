## 🔥 프로젝트 개요

**GreenTable**은 소비자와 생산자 간의 신뢰를 기반으로 한 **친환경 농산물 쇼핑몰 SaaS 플랫폼**입니다.  
기존의 온라인 마켓에서는 친환경 인증 여부 확인이 어렵고, 중간 유통 과정이 복잡하여 생산자는 제값을 받기 힘들며, 소비자 또한 신뢰할 수 있는 제품을 구매하기 어려운 상황입니다.  
저희는 이러한 문제점을 해결하고자 **생산자 중심의 시스템**, **관리자 농가 승인 기반의 품질 유지**, 그리고 **간편한 주문 및 배송 프로세스**를 갖춘 서비스를 기획하게 되었습니다.

</br>

<details> 
<summary><b>1. 생산자의 판로 확보 어려움</b></summary> 

</br>
  
소규모 농가는 직접 판매를 하기 위해 SNS 마케팅, 지역 마켓 입점 등 다양한 노력을 하지만,  
- 접근성이 낮고,  
- 신뢰 기반의 소비자 확보가 어렵습니다.  
- 중간 유통 과정에서 수수료로 인해 실제 수익이 낮아집니다.

**GreenTable**은 관리자가 승인한 농가 정보를 기반으로, 해당 농가의 상품을 시스템에 등록하고,
소비자는 후기와 평점을 통해 농가와 신뢰 관계를 형성할 수 있도록 지원합니다.

</br>

</details> 

<details> 
<summary><b>2. 소비자의 친환경 인증 확인 불가</b></summary> 

</br>

대형 온라인 쇼핑몰에서는 ‘친환경’, ‘유기농’ 등의 키워드로 상품이 올라오지만,  
- 인증 여부가 불투명하고  
- 후기 또한 마케팅성이 강한 경우가 많습니다.  
- 직접 비교하기도 어렵습니다.

**GreenTable**은 관리자 승인제로 상품 등록을 제한하고,  
실제 구매자가 후기를 작성하여 **정직한 정보 제공**을 가능하게 합니다.

</br>

</details> 

<details> 
<summary><b>3. 복잡한 주문 과정과 불편한 UI</b></summary>
  
</br>
  
기존 농산물 공동구매 플랫폼이나 SNS 기반 판매는  
- 문의 → 입금 → 주소 전달 → 배송 확인 등  
매우 **비효율적인 프로세스**로 이루어집니다.

**GreenTable**은 웹 기반 쇼핑몰 UI를 도입하여,  
- 장바구니, 찜, 자동 주문  
- 배송지 등록, 주문 내역 조회  
등의 기능을 통해 간편한 사용자 경험을 제공합니다.

</br>

</details>

## 📝 설계 및 구현

**GreenTable**은 다양한 사용자 유형(소비자, 농가, 관리자)에 따라 각각의 역할을 분리하고,
각 사용자 흐름에 맞는 UI/UX를 제공하도록 설계된 SaaS 플랫폼입니다.
전체 시스템은 **Jakarta EE 기반의 MVC 패턴**으로 구현되었으며,
**Docker Compose로 컨테이너화**하여 EC2에 배포됩니다.

</br>

<details>
<summary><b>시스템 개요</b></summary>

</br>

친환경 농산물 유통의 효율성과 신뢰성을 확보하기 위해,
소비자, 농가, 관리자 각각의 요구사항을 충족하는 시스템을 기획하였습니다.

* **소비자**: 쉽고 빠르게 상품을 검색, 장바구니 담기, 결제 및 후기 작성 가능
* **농가**: 소개 페이지를 통해 브랜드 스토리 및 정보 공개
* **관리자**: 상품 등록, 승인, 통계 확인, 사용자 관리 등 서비스 운영의 중심 역할

</br>

<details>
<summary><b>시스템 아키텍처</b></summary>

</br>

**MVC 패턴** 기반으로 Presentation → Controller → Service → DAO → DB 로 흐름이 분리되어 있고,
**DispatcherServlet**은 **Reflection API**를 통해 동적으로 요청을 라우팅합니다.
JNDI + JDBC 이중 연결 방식을 통해 **99.9%의 연결 안정성**을 확보하였으며,
**Docker Compose**로 `MySQL`과 `GreenTable App`을 각각 컨테이너화하여 EC2에서 운영 중입니다.

### 시스템 아키텍처

* MVC 기반 Jakarta EE 10
* DispatcherServlet + Reflection API 동적 라우팅
* JNDI + JDBC 이중 연결 방식으로 99.9% DB 안정성
* Docker Compose 기반 MySQL, App 컨테이너 운영

### 컨테이너 구성도

```
AWS EC2 (Ubuntu 22.04)
├── Docker Compose
│   ├── MySQL 8.0 (Port 3306, Volume Mount, healthcheck)
│   └── GreenTable App (Tomcat 10.1, JDK 17, Port 8080)
```

### 요청 처리 워크플로우

```
사용자 요청 → JSP + JSTL → DispatcherServlet → Controller → Service → DAO  
→ JNDI 우선 DB 연결 → (실패 시) Direct JDBC → MySQL 응답 → View 렌더링
```

</br>

백엔드는 Jakarta EE 10을 기반으로 Reflection API를 활용한 동적 라우팅 시스템을 구현하였고, JNDI DataSource와 Direct JDBC의 이중 연결 방식으로 99.9% 연결 안정성을 확보했습니다. 데이터베이스는 MySQL 8.0을 Docker 컨테이너로 운영하며, PreparedStatement 100% 적용으로 완벽한 보안을 구현했습니다.

프론트엔드는 JSP + JSTL 3.0을 사용하여 Server-Side Rendering 방식으로 구현했으며, AJAX 기반 비동기 통신으로 사용자 경험을 향상시켰습니다. 역할 기반 세션 관리를 통해 관리자/농가/일반 사용자별 차별화된 UI를 제공합니다.

* 📈 서비스 운영 지표 확인 (리뷰 수, 찜 수, 회원 수 등)
* 🔧 시스템 설정 관리 (배너, 분류, 공지사항 등)

<summary><b>Reflection 기반 동적 라우팅</b></summary>

```java
protected void service(HttpServletRequest req, HttpServletResponse res) {
    String key = req.getParameter("key");
    String methodName = req.getParameter("methodName");
    Controller controller = controllerMap.get(key);
    Method method = controller.getClass().getMethod(methodName, HttpServletRequest.class, HttpServletResponse.class);
    ModelAndView mv = (ModelAndView) method.invoke(controller, req, res);
}
```

```java
public static Connection getConnection() throws SQLException {
    if (dataSource != null) {
        try {
            Connection conn = dataSource.getConnection();
            if (conn != null && !conn.isClosed()) return conn;
        } catch (SQLException e) {
            System.err.println("JNDI 연결 실패, Direct 연결로 전환");
        }
    }
    return DriverManager.getConnection(JDBC_URL, USER, PASS);
}
```
